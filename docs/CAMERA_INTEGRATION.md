# 실제 CCTV 탑뷰와 연결

## 먼저 구분할 정보

| 정보 | 실제 취득 방법 | 현재 합성 팩 |
|---|---|---|
| 바닥 길이·폭·위치 | 보정된 탑뷰 영상, 높이/원근 보정 | 참 치수에 수치 오차를 더함 |
| 박스 높이 | SKU 명세, 깊이/측면 센서, 복수 관측 등 | 공칭 SKU 높이 |
| 박스 무게 | 저울 또는 SKU 공칭값 | 현재는 저울, 미래는 SKU 공칭값 |
| SKU 식별 | 태그/바코드/WMS 연동 또는 검증된 분류 | WMS identity를 확인했다고 가정 |
| 도착 순서 | 연속 프레임 추적, 컨베이어 방향·속도·분기 정보 | 한 줄·추월 없음 |
| 누락·가림·추적 연속성 | 시간 이력·입출구 관측/센서로 확인 | 합성 추적 연속성 플래그 |

일반 RGB 탑뷰 한 장에서 높이·무게가 자동으로 정확히 나온다고 가정하면 안 됩니다. OpenCV의 호모그래피 설명도 평면 사이의 변환을 다룹니다. 컨베이어 바닥에서 보정한 스케일을 높이가 다른 박스 윗면에 그대로 적용하면 오차가 생길 수 있습니다. 높이 정보와 카메라 보정을 함께 사용하고 실제 치수와 비교해야 합니다.

## 연결 절차

1. 카메라 왜곡·픽셀/실제 좌표 변환과 ROI를 보정합니다.
2. 연속 프레임에서 박스 id를 유지하며 위치·규격·신뢰도를 기록합니다. 합성 bbox 파일로 영상 검출기를 학습했다고 표현하지 않습니다.
3. 컨베이어 한 줄/추월 없음/분기 없음 가정을 확인합니다. 다중 라인·버퍼·분기에서는 경로와 통과 게이트를 별도로 모델링합니다.
4. ‘적재 지점까지 이어지는 순서가 확인된 구간’만 verified prefix로 전달합니다. 가려진 박스 뒤의 검출은 불확실한 힌트로 남깁니다.
5. 시간 지연·정지·가림으로 정보가 오래되면 다시 확인합니다. 누락 여부를 확인하지 못한다면 coverage_complete를 임의 true로 쓰지 않습니다.
6. 현재 박스가 측정 지점에 도착하면 실측과 예측을 비교하고, 차이가 허용 범위를 넘으면 재측정·재계획합니다.

실제 추적 모듈은 다음 정보를 관측 생성기에 넘기면 됩니다: timestamp, track_id, SKU 후보/확정 여부, bbox와 실제 길이·폭 추정, 오차 또는 신뢰도, 도착시간 범위, 가림 여부, 추적 연속성. v2는 위치 순서를 단순화했으므로 타임스탬프·도착시간 구간·카메라 지연은 확장 필드입니다.

영상 모델을 학습하려면 실제/렌더링 영상과 검출·분할·추적 정답을 별도로 모아야 합니다. 현재 데이터는 **적재 의사결정 AI를 위한 수치 관측 데이터**입니다.

기술 참고: https://docs.opencv.org/4.x/d9/dab/tutorial_homography.html
