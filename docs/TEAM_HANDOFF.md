# 팀원이 붙일 함수와 첫 확인사항

| 파트 | 가져갈 파일 | 연결할 작업 |
|---|---|---|
| 후보 생성·적재 정책 | packing.py, observe.py, sample_observations.json | 후보 생성기 교체, 현재+확인된 미래+미관측 재고로 결정 |
| 평가·데이터 | teacher.py, labels.py, validate.py, manifest | 점수/물성/예외 규칙 조정, 표적 생성과 분할·누출 확인 |
| 화면·로봇 | topview_viewer.html, sample_observations.json | 3D 화면, ROS 메시지, 가반하중·그리퍼·접근·경로 충돌 연결 |

각자 작은 smoke 데이터가 실행되는지 먼저 확인합니다. 코드를 수정할 때 변경한 후보 생성·마스크·교사 점수의 버전과 설정을 함께 기록하고, 이전 표적에 새로운 특징 순서를 섞지 않습니다.

## 회의에서 확정할 항목

1. 실제 탑뷰 시야와 대략적인 박스 간격에서 몇 개의 연속 순서를 확인할 수 있는가?
2. SKU·높이·무게는 어디서 얻고, 누락·가림·오래된 추적 정보는 언제 재확인하는가?
3. 예외 박스의 목적지·버퍼·팔레트 전환·재배치는 허용하는가? 지금 기본 환경은 손상 별도 목적지 외에는 순서 변경·재배치·새 팔레트 전환을 구현하지 않았다.
4. 상대 무게·한 상자의 100% 지지 규칙을 초기 버전에서 유지할 것인가? 확장하려면 다중 지지·하중 전파 정책을 일관되게 바꿔야 한다.
5. AI는 후보 점수/상위 K 선별로 시작할 것인가, 강화학습까지 진행할 것인가?
6. 후보 수·미래 깊이·샘플 수·결정 시간 예산을 어떻게 고정할 것인가?
7. 실제 로봇 검증을 완료한 후보와 NOT_CHECKED 후보를 결과에서 어떻게 구분할 것인가?

## 첫 공유 후 권장 결과물

- 동일한 시험 가족을 이용한 2/4/8/12 카메라별 적재 개수·부피·결정 시간 비교.
- 현재-only/관측 미래/미관측 샘플링/AI 선별의 효과를 나눠 보여 주는 비교.
- 가림 사례에서 잘못된 순서를 강제로 연결하지 않는 입력·결정 로그.
- 정상 기준과 혼합 스트레스 사례의 결과 분리. 적재 실패가 전체 부피 초과인지, 후보 생성기 한계인지, 지지·하중 차단인지 설명.
- 실제 데이터가 제공되면 합성 팩의 단위·스키마로 매핑한 작은 시험 세트. 공식 데이터는 팀이 정한 접근·배포 범위에 맞춰 별도로 관리.
