# 데이터 카드

## 목적과 출처

PAC2026 분과2 IR 아이디어를 구체화하고 적재 의사결정 알고리즘을 개발하기 위한 합성 자료입니다. 생성 코드 버전 2.0.0, 시드 20261004입니다. 실제 산업 현장 분포를 추정한 자료는 아닙니다. 기존 팩의 5종 SKU에서 12종으로 확장했고, 입고 목록뿐 아니라 관측 모델·적재 환경·후보 학습 표적을 추가했습니다.

## 규모와 분할

기본 재고 250개, 재고당 48~80개 박스, 12개 시나리오, 4개 카메라 프로필입니다. 12,000개 에피소드, 총 770,496개 박스 입력입니다. 같은 기본 재고를 여러 시나리오·카메라로 반복하므로 관측 행이 모두 독립 표본은 아닙니다.

그룹 단위 train/validation/test = 175/37/38, 에피소드 = 8,400/1,776/1,824입니다. 같은 재고의 모든 순서·센서 변형이 한 분할에 들어갑니다. 모든 분할은 동일한 12개 SKU 이름과 치수 범위를 사용하므로, 미지의 SKU/산업 환경으로 일반화하는 시험은 아닙니다. 새 SKU·새 치수 범위·실제 센서 분포는 별도 OOD 시험으로 구성하세요.

후보 학습 표적은 train 400 / validation 80 / test 80 에피소드를 저장소 전체에서 시드 기반 reservoir sampling으로 고른 뒤 생성합니다. 최대 36개 입력까지 처리하며 3개 간격으로 상태를 기록합니다. 후보 부족·조기 종료에 따라 상태 수가 달라집니다. 배포본은 train/validation/test 상태 2,233/469/460개, 후보 표적 16,781/3,516/3,485개입니다. 총 상태 3,162개, 유효 후보 표적 23,782개입니다.

20%의 재고 그룹은 동일 S 또는 M을 반복하는 정상 기준 사례입니다. 실제 치수·무게 변동을 끄고 충분한 규격·무게 한도를 사용해 정상 완료 상태도 수집합니다. 나머지 80%는 12종 혼합 스트레스 사례로 치수·질량 변동과 다양한 팔레트를 사용합니다. 전체 물량이 단일 팔레트의 부피·무게를 넘는 사례도 있을 수 있으며, 단일 팔레트에서 모든 에피소드의 완료를 보장하는 데이터는 아닙니다. 평가는 이 두 프로필을 구분해 확인하세요.

## 변형

- SKU 공칭 길이·폭·높이 스케일 0.85/1/1.1, 실제 박스 치수 ±1%, 실제 질량 ±2%.
- 그룹별 질량·상부 한도 편차, 일부 SKU의 90도 회전 불허.
- 팔레트 길이 1.0/1.2/1.4, 폭 0.8/1.0/1.2, 허용 높이 0.6/0.9/1.2 m, 총무게 한도 120/200/300 kg.
- 탑뷰 길이·폭 표준편차 2/8/15 mm. 검출 누락·가림은 프레임별 합성 확률입니다.
- 박스 간 간격 5~20 cm, 카메라 시야 1.1/2/3.8/5.6 m, 최대 추적 수 2/4/8/12.
- 손상 목적지 분리, 무게 누락·치수 신뢰도 부족 후 재측정, 처리 10개 후 팔레트 확대.

이 값들은 장비나 주최측 사양이 아닙니다. 생성기에는 합성 센서 바이어스·조명·렌즈 왜곡·영상 분류 오류·가짜 검출·추월·분기·장시간 프레임 손실을 물리적으로 구현하지 않았습니다. 현재 가림의 프레임 간 상관관계도 실제 추적 데이터에서 추정하지 않았습니다.

## 하중·물리 가정

한 하부 상자의 바닥 전체 지지, 상부 박스가 바로 아래보다 무겁지 않음, 상부 질량×9.81이 지지 체인을 통해 누적된다는 규칙을 사용합니다. 다중 지지, 포장재 변형, 편심 접촉·마찰, 동적 미끄러짐·붕괴는 포함하지 않습니다. 공칭 하중 한도가 실제 포장 강도를 보장하지 않습니다.

## 표적의 성격

교사는 정책 관측만 받아 수량을 보존한 미래 2개를 샘플링하고 최대 12단계를 단순 탐욕 방식으로 이어갑니다. 유효 후보 최대 8개 내의 미래 평가를 표적으로 사용합니다. 많은 시나리오의 12단계 결과는 단일 미래 정답이 아니라 가능한 결과의 근사입니다. 2개 샘플의 최소값은 전체 확률분포의 하위 분위수가 아닙니다.

교사 점수의 무게중심 위치 항목은 균형 대용 지표이고, 로봇의 작업시간 항목은 아직 포함하지 않았습니다. 계산 시간을 재는 것과 로봇 실행 시간을 예측하는 것은 별개입니다. 주최측 기술 요구를 모두 구현한 최종 평가 모델이라고 표현하면 안 됩니다.

## 배포와 사용

원본/표적/모델에는 실제 사람·현장 영상·공식 데이터가 없습니다. 팀 공유용이며 공개 배포 라이선스는 팀이 정한 뒤 추가합니다. 코드가 기대하는 데이터의 구조와 범위를 실제 제공 데이터에 맞춰 매핑해 사용하세요. 프로젝트 설명에서 합성·실제·예측·측정 항목을 구분합니다.
